# 월간로그 (Monthly Log) 서비스 기획서

## 1. 개요 및 목적

### 서비스 명칭
**월간로그 (Monthly Log)**

### 목적
- 블로그 스터디원들의 글쓰기 및 댓글 활동을 실시간으로 집계하고 시각화
- 노션 등에 수동으로 기록하는 번거로움 제거
- 상호 학습 독려 및 활동 투명성 확보

### 핵심 미션
**매월 글 2개 이상 + 댓글 10개 이상 작성 시 미션 통과**

---

## 2. 사용자 및 권한 체계

### 가입 승인 절차
GitHub 소셜 로그인 후, 운영진의 승인을 받아야 정식 기능 사용 가능

| 구분 | 상태 | 주요 권한 |
|------|------|-----------|
| **미승인 유저** | `PENDING` | 로그인 후 가입 승인 대기 화면만 노출 (기타 기능 접근 불가) |
| **정식 회원** | `APPROVED` | 글/댓글 등록, 대시보드 및 멤버 활동 현황 조회 가능 |
| **반려된 유저** | `REJECTED` | 반려 사유 확인 가능, 재가입 불가 |
| **운영진** | `ADMIN` | 유저 승인/반려 처리, 사용자 강제 탈퇴(계정 삭제) 관리 |

---

## 3. 화면 구조 (Information Architecture)

### 3.1 로그인 페이지
- GitHub 소셜 로그인 버튼 제공
- 로그인 후 권한에 따라 자동 리다이렉트

### 3.2 승인 대기/반려 페이지
- **PENDING**: 승인 대기 메시지 노출
- **REJECTED**: 운영자의 반려 사유 노출

### 3.3 메인 페이지 (정식 회원 전용)
- **월간 캘린더**: 모든 사용자의 활동이 표시되는 캘린더 뷰
  - 날짜별로 작성된 글 개수 표시
  - 클릭 시 해당 날짜의 글 목록 필터링
- **전체 글 목록**: 현재 선택된 월의 모든 사용자 글
  - 작성자 정보 (프로필 이미지, 이름)
  - 글 제목, URL, 작성일
  - 댓글 수 표시
- **개인 진행률 위젯**: 우측 사이드바 또는 상단에 간단히 표시
  - 이번 달 내 글 x/2, 댓글 y/10
  - 목표 달성 배지 🎉

### 3.4 전체 활동 피드
- 모든 멤버가 등록한 글의 최신 목록
- 멤버별 달성 현황 카드 (프로필 이미지, 이름, 진행률)

### 3.5 글 상세 및 댓글
- 등록된 글의 상세 내용 확인
- 댓글 작성/수정/삭제 (본인 댓글만)

### 3.6 운영 관리 페이지 (ADMIN 전용)
- 신규 가입자 승인/반려 처리
- 전체 회원 목록 및 상태 관리
- 사용자 강제 탈퇴 기능

## 4. 핵심 서비스 로직

### A. 활동 집계 및 월간 기준

#### 시간대
- 모든 데이터는 **한국 표준시(KST)** 기준으로 기록

#### 월간 경계
- 매월 **1일 00:00:00 KST**를 기점으로 새 달의 집계 시작

#### 실시간 반영
- 글 등록 및 댓글 작성 시 대시보드의 진행률 수치 즉시 갱신

### B. 글(Post) 등록 규칙

#### 필수 항목
- **제목** (title)
- **URL** (url)
- **설명** (description) - 선택 사항

#### 중복 차단
- 동일한 사용자가 이미 등록한 URL을 중복해서 등록할 수 없음

#### 자동 기록
- 등록 시점의 날짜가 시스템에 의해 자동으로 기록됨 (created_at)

### C. 댓글(Comment) 작성 정책

#### 중복 제한
- **사용자당 한 글에 1개의 댓글만 인정**
- 동일 글에 여러 번 작성해도 월간 카운트는 1만 증가

#### 카운팅
- 댓글 작성일이 속한 월의 통계에 합산
- 삭제 시 해당 월의 누계에서 즉시 차감

#### 수정
- 작성자 본인만 가능
- 수정은 카운트 수치에 영향을 주지 않음

## 5. 주요 기능 명세

### 5.1 개인 진행률 및 목표 관리
- 대시보드 상단에 이번 달 통과 여부를 배지(🎉) 형태로 표시
- 목표 미달성 시 "글 n개, 댓글 m개 더 필요" 가이드 실시간 노출

### 5.2 전체 활동 피드
- 최신 글 목록 (무한 스크롤 또는 페이지네이션)
- 각 글에 댓글 수 표시

### 5.3 멤버 활동 현황
- 전체 멤버의 이번 달 진행률 카드 형태로 표시
- 달성/미달성 상태 시각적 구분

### 5.4 댓글 시스템
- 글 상세 페이지에서 댓글 작성
- 본인 댓글 수정/삭제 가능
- 댓글 작성 시 실시간으로 개인 진행률 업데이트

### 5.5 운영 관리
- 신규 가입자 목록 (PENDING 상태)
- 승인/반려 처리 (반려 시 사유 입력 필수)
- 전체 회원 목록 및 상태 변경
- 사용자 강제 탈퇴 (계정 삭제)

## 6. 데이터베이스 스키마

### 6.1 users (사용자)
```sql
- id: UUID (PK)
- github_id: TEXT (UNIQUE)
- email: TEXT
- name: TEXT
- avatar_url: TEXT
- role: ENUM ('PENDING', 'APPROVED', 'REJECTED', 'ADMIN')
- rejection_reason: TEXT (nullable)
- created_at: TIMESTAMP
- updated_at: TIMESTAMP
```

### 6.2 posts (글)
```sql
- id: UUID (PK)
- user_id: UUID (FK -> users.id)
- title: TEXT
- url: TEXT
- description: TEXT (nullable)
- created_at: TIMESTAMP
- updated_at: TIMESTAMP

UNIQUE(user_id, url) -- 중복 URL 방지
```

### 6.3 comments (댓글)
```sql
- id: UUID (PK)
- post_id: UUID (FK -> posts.id)
- user_id: UUID (FK -> users.id)
- content: TEXT
- created_at: TIMESTAMP
- updated_at: TIMESTAMP

UNIQUE(post_id, user_id) -- 한 글에 한 사람당 1개 댓글만
```

## 7. 우선순위 및 개발 단계

### Phase 1: MVP (필수 기능)
1. ✅ 로그인/회원가입 (GitHub OAuth)
2. ✅ 글 URL 업로드 및 댓글 달기
3. ✅ 메인 대시보드 (개인 진행률)

- 월별 통계 및 히스토리
- 알림 기능 (목표 미달 시 리마인더)
- 멤버 랭킹 시스템
- 다크모드 지원

## 8. 기술 스택 (확정)

- **프레임워크**: Next.js 16 (App Router)
- **언어**: TypeScript
- **스타일링**: Tailwind CSS 4 + clsx + CVA
- **백엔드**: Supabase (Auth, Database, Storage)
- **상태 관리**: Zustand (전역), TanStack Query (서버)
- **인증**: GitHub OAuth (Supabase Auth)
- **배포**: Vercel

## 9. 비기능 요구사항

### 반응형 디자인
- 모든 페이지는 모바일/태블릿/데스크톱 대응 필수

### 성능
- 초기 로딩 시간 3초 이내
- 실시간 데이터 반영 (Supabase Realtime)

### 접근성
- ARIA 레이블 적용
- 키보드 네비게이션 지원

### 보안
- Row Level Security (RLS) 적용
- CSRF 방지
- XSS 방지 (입력값 sanitize)
