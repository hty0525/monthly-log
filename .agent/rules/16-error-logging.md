# 에러 기록 규정 (Error Logging)

## 목적
- 발생한 에러의 원인과 해결 과정을 기록하여 동일한 문제의 재발을 방지합니다.
- 어떤 작업을 하던 중 에러가 발생했는지 작업 맥락(Context)을 파악하여 근본적인 원인을 해결합니다.

## 기록 규칙

### 1. 기록 시점
- 해결에 10분 이상 소요된 에러
- 설정이나 아키텍처와 관련된 중요 에러
- 반복적으로 발생하는 에러

### 2. 기록 항목
- **발생 일시**: 에러가 발생한 시간
- **작업 맥락**: 어떤 기능을 구현하거나 어떤 명령어를 실행하던 중이었는지 상세히 기술
- **에러 메시지**: 시스템이나 터미널에 노출된 에러 내용 (스크린샷 포함 가능)
- **원인 분석**: 에러가 왜 발생했는지에 대한 가설 및 확인된 원인
- **해결 방법**: 문제를 어떻게 해결했는지 단계별로 기록
- **재발 방지 대책**: 미래에 같은 실수를 하지 않기 위한 조치 (규칙 업데이트 등)

### 3. 저장 위치
- 프로젝트 루트의 `docs/error_log/` 폴더 내에 마크다운 파일로 저장
- 파일명 형식: `YYYY-MM-DD-에러-요약.md` (kebab-case)

## 에러 로그 템플릿

```markdown
# [에러 요약]

## 📅 발생 일시
- 202X-XX-XX

## context 작업 맥락
- (예: pnpm 환경에서 스토리북을 초기화하고 실행하던 중)

## ❌ 에러 메시지
- ```bash
  (에러 내용 복사)
  ```

## 🔍 원인 분석
- (왜 발생했는지 기술)

## ✅ 해결 방법
- (어떻게 고쳤는지 기술)

## 🛡️ 재발 방지 대책
- (규칙에 추가하거나 설정을 변경한 내용)
```
